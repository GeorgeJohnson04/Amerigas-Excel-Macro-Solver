# KiroSolver — native Excel supply-plan solver (replaces OpenSolver)

`KiroSolver.bas` is a single VBA module that solves the propane supply-planning
models **inside Excel**, with **no OpenSolver and no Python**. It reproduces the
OpenSolver result and writes the same decision cells, in seconds instead of
hours. Import it once per workbook.

---

## Install (one time per model workbook)

1. Open the model workbook (`.xlsm`) and **Enable Content** (macros must be on).
2. Open the VBA editor: **Alt + F11**.
3. **File → Import File…** and pick `KiroSolver.bas`
   (or drag the file onto the *Project* pane on the left).
   - You should see a module named **KiroSolver** appear under *Modules*.
4. **Save** the workbook (keep the `.xlsm` / macro-enabled format).
5. Close and reopen the workbook once. This lets it register the
   **Ctrl + Shift + K** shortcut.

> One-time trust setting (if import is blocked): File → Options → Trust Center →
> Trust Center Settings → Macro Settings → tick **"Trust access to the VBA
> project object model."** (You already enabled this during development.)

## Run

- Press **Ctrl + Shift + K**, **or** press **Alt + F8**, choose **SolveModel**, and click Run.
- A message box reports the outcome:
  - `KIRO OPTIMAL. Cost = … | … s | verified OK` — solved; the decision cells
    (lift %, shipments, storage) are filled in and `D4` shows the cost.
  - `KIRO: INFEASIBLE …` — no valid plan exists for the current inputs. It tells
    you the size of the gap and **leaves your inputs untouched**.

Nothing is written unless the answer passes a check against the workbook's own
constraint formulas, so a bad solve can never overwrite your model.

---

## How it works (short version)

It reads the model straight from the workbook's own Solver names
(`solver_adj`, `solver_lhs*`, `Period*_p_*`, …), solves it as a minimum-cost
network flow (successive-shortest-paths), writes the decision cells, then
re-checks every constraint and the objective against Excel's own formulas
before keeping the result. It reads the model size on every run, so adding
supply points, demand points, or periods does **not** break it — as long as the
new rows sit inside the model's named ranges (i.e. the model was regenerated by
the MixedFormulator, or the ranges were extended to cover them).

## Lane on/off rule (as requested)

- A **blank** freight/transport cell = a **closed** lane (never shipped).
- A **numeric** freight cost — **including 0** (a delivered load) = a **usable** lane.

The current models have no blank freight cells, so existing results are
unchanged. Going forward, **clear a freight cell to forbid that lane**; set it
back to a number (0 or a rate) to allow it again.

## Reading an INFEASIBLE message

The message states total demand vs. maximum available supply, e.g.
`[total demand=22,843, max available supply=21,088 …]`. Common causes:

- **Not enough supply** — demand exceeds what the contracts (% max) plus starting
  inventory can deliver.
- **Forced minimum lifts exceed demand** with no storage to absorb them — lower
  the % minimums or open storage.
- **Contradictory min/max bounds** — an input's minimum is above its maximum, so
  no value can satisfy both (e.g. *UT-CO Working*: supply #6, periods 7–12 have
  a 75% minimum take but a 70% maximum). Fix the input cells.

These are real conditions in the current data — OpenSolver would report the same.

## Validation notes

- Where a model's inputs are unchanged since its last OpenSolver run, KiroSolver
  matches OpenSolver **to the penny** (verified on the Alaska, IL-IN, Carolinas,
  FL Spur, S TX, and West Rail Terminal baselines, among others).
- Where inputs were edited after the last OpenSolver save, KiroSolver re-solves
  the **current** data. The old cost stored in `D4` can be stale — in those files
  the previously-saved solution no longer satisfies the current constraints.

### Known data conditions to be aware of

- **UT-CO Working** — contains a contradictory min/max (min take > max take), so
  it is correctly reported infeasible until the input is corrected.
- **East Rail Baseline** — currently has **zero demand** entered, so the optimum
  is 0 (nothing to ship). Check the demand inputs if that is unexpected; the old
  `D4` value is from a prior scenario.
- **FL Spur Working** — solves to within ~0.016% of its last saved value (a few
  thousand dollars on ~$72M), well within planning tolerance.
